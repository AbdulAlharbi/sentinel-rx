Hackathon challenge: Agentic Recovery of a Failing System

Sentinel-RX

A security-aware agent that identifies, diagnoses, recovers and verifies the recovery of a failing enterprise system, plus a reproducible benchmark that proves it on unseen incidents. 100% local, 100% free: a 7B model via Ollama, no Docker, no cloud.

The problem

State-of-the-art agents solve roughly 11% of realistic incidents (OpenRCA, ITBench), and no AIOps benchmark tests a security threat hidden inside an operational failure. Five gaps from the literature review drive the design: G1 concurrent faults, G2 security incidents inside ops incidents, G3 false "recovered" claims, G4 the cost of the agent itself, G5 robustness on unseen combinations and degraded telemetry.

Approach

  • Hybrid. Cheap deterministic detectors turn 4 000 flow records and 2 000 log lines into a ~600-token ranked evidence list; the LLM reasons over that, never over raw telemetry.
  • Security-aware. A RandomForest beacon detector finds C2 call-backs hidden among health checks and update polls; the safety layer enforces contain before restart.
  • Verification gate. "Recovered" may only be claimed when post-action telemetry matches the pre-incident baseline and no (blocked) beacon attempts remain.
  • Reproducible. Seeded simulator, strict dev/held-out split enforced in code, record/replay LLM cache, bootstrap CIs over seeds. The same agent runs on a live system of five real processes.
